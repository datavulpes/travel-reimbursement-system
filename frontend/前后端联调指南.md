> 适用工程：`金舟面试项目/前端`（Vue 3 + Vite 5）+ `Tutor-Student Matching Platform/travel-server`（Spring Boot 4.1.1 + Java 21）
> 目标：把现在跑在 Mock 上的 14 个页面，逐个切换到真实接口上，并且在 nginx 下能跑。
>
> **2026-09-23 状态**：后端 37 个接口全部实现，Apifox 已逐步测通（见逐步版对照文档），
> 本文第二、三节的骨架与约定都已落地。前端 `.env.development / .env.production` 已切成
> `VITE_USE_MOCK=false`，**直接进第四节 Step 3 全链路验收即可**，排查看第五节。

## 一、先认清三种运行形态

联调不是一步到位的，中间要在三种形态之间切。**同一个 `.env` 开关控制，不要乱改业务代码。**

| 形态 | 用途 | 怎么开 | 请求去哪了 |
|---|---|---|---|
| A. Mock 演示 | 答辩、给队友看效果、后端还没好 | `VITE_USE_MOCK=true` | 不发网络，被 axios adapter 拦截，由 `src/mock/index.js` 应答 |
| B. 开发联调 | **日常联调用这个**，`npm run dev` | `VITE_USE_MOCK=false` | Vite 代理 `127.0.0.1:5173/api/*` → `127.0.0.1:8080` |
| C. nginx 形态 | 部署验收、模拟真实环境 | `VITE_USE_MOCK=false` + `npm run build` | nginx `:8088` 同源请求，反代到 `:8080` |

**三个开关的位置：**

- `前端/.env.development` → 形态 A/B 切换（`npm run dev` 读它）
- `前端/.env.production` → 形态 C（`npm run build` 读它）
- `vite.config.js` 里的 `proxy.target` → 后端端口，默认 8080

改完 `.env` 必须重启 dev server（Vite 不会热更新环境变量）。
启动后看控制台第一行 `[api] 数据源=…`：`本地 Mock（不发请求）` 说明还在形态 A，
要看到 `真实后端 /api` 才是形态 B。

## 二、后端必须先对齐的六件事

这六件有一件没对齐，前端页面就是白屏或一直转圈。**先花半小时把它对齐，比后面排查三天划算。**

### 1. 端口必须是 8080

`vite.config.js` 的 proxy 和 `deploy/nginx.conf` 的 upstream 都写死了 `127.0.0.1:8080`。要改端口，这两处同步改。

```yaml
server:
  port: 8080
```

### 2. 统一返回体（最重要）

前端 `request.js` 里写死了这个判断：**有 `code` 字段就当统一返回体处理，`code === 0` 才算成功，成功后直接把 `data` 抛给页面；非 0 就用 `msg` 弹红色提示。**

所以 Controller 必须全部返回 `R`，**不要直接返回实体或 List**。

```java
@Data
public class R<T> {
    private int code;      // 0 = 成功
    private String msg;
    private T data;

    public static <T> R<T> ok(T data) {
        R<T> r = new R<>();
        r.code = 0; r.msg = "ok"; r.data = data;
        return r;
    }
    public static <T> R<T> ok() { return ok(null); }

    public static <T> R<T> fail(int code, String msg) {
        R<T> r = new R<>();
        r.code = code; r.msg = msg;
        return r;
    }
}
```

### 3. 分页结构

前端 `dict.js` / 列表页读的是 `list / total / pageNum / pageSize` 四个字段，**名字不能换成 records、rows、count**。

```java
@Data
public class PageResult<T> {
    private List<T> list;
    private long total;
    private long pageNum;
    private long pageSize;

    public static <T> PageResult<T> of(IPage<T> page) {
        PageResult<T> r = new PageResult<>();
        r.list = page.getRecords();
        r.total = page.getTotal();
        r.pageNum = page.getCurrent();
        r.pageSize = page.getSize();
        return r;
    }
}
```

### 4. Token 传递方式：`Authorization: Bearer <token>`

前端在请求拦截器里把 localStorage 的 `TE_TOKEN` 塞进请求头，字段名固定。后端拦截器这样取：

```java
String auth = request.getHeader("Authorization");   // 注意不是 token，不是 X-Token
String token = auth != null && auth.startsWith("Bearer ") ? auth.substring(7) : null;
```

**登录接口一定要放行**，否则永远登不进去（见第 2 节的拦截器代码）。

token 失效时返回 `code=4001` 或直接 HTTP 401，前端都会自动清 token 跳回登录页。

### 5. 错误码表（必须与设计报告 7.5 一致）

| code | 含义 | 前端行为 |
|---|---|---|
| 0 | 成功 | 透出 data |
| 1001 | 参数校验失败 | 弹 msg |
| 2001 | 发票重复 | 弹 msg（票据挂接页会高亮） |
| 2002 | 当前状态不允许该操作 | 弹 msg |
| 2003 | 超出差标但未填写超标说明 | 弹 msg |
| 2004 | 预检未通过，需填写强制说明 | 弹 msg（报销提交页引导填说明） |
| 3001 | 无操作权限 | 弹 msg |
| 4001 | 登录失效 | 弹 msg → 清 token → 跳登录 |
| 5000 | 系统异常 | 弹 msg |

建议后端建个枚举或常量类，不要散落在各个 Service 里写魔法数字。

### 6. 文件上传上限

手机拍的票据 3–5MB，Spring Boot 默认 1MB 会直接 413。

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB
```

nginx 侧已经配好 `client_max_body_size 10m`，两边保持一致。

## 三、后端起步骨架（建议先写这五个类）

这五个类写完，`I-01` 登录就能联调通了。

**① `common/R.java` + `common/PageResult.java`** —— 见上一节。

**② `common/BusinessException.java` + `GlobalExceptionHandler.java`**

```java
@Getter
public class BusinessException extends RuntimeException {
    private final int code;
    public BusinessException(int code, String msg) { super(msg); this.code = code; }
}

@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusiness(BusinessException e) {
        return R.fail(e.getCode(), e.getMessage());
    }
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldError() == null
                ? "参数校验失败" : e.getBindingResult().getFieldError().getDefaultMessage();
        return R.fail(1001, msg);
    }
    @ExceptionHandler(Exception.class)
    public R<Void> handleOther(Exception e) {
        e.printStackTrace();
        return R.fail(5000, "系统异常：" + e.getMessage());
    }
}
```

业务里直接 `throw new BusinessException(2001, "该发票号已存在")`，Controller 一个 try-catch 都不用写。

**③ `config/WebConfig.java`（跨域）**

形态 B/C 下是同源请求，其实用不到 CORS。但你在 Apifox 里直连 8080，或者用 Postman 打的时候需要：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}
```

**④ `interceptor/TokenInterceptor.java`**

```java
@Component
public class TokenInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        String uri = request.getRequestURI();
        if (!uri.startsWith("/api/")) return true;
        if (uri.startsWith("/api/system/login")) return true;   // 登录必须放行

        String auth = request.getHeader("Authorization");
        if (auth == null || !auth.startsWith("Bearer ")) {
            writeJson(response, 4001, "登录已失效，请重新登录");
            return false;
        }
        String token = auth.substring(7);
        // TODO: 校验 token 合法性并把 userId/role 放进 ThreadLocal
        return true;
    }

    private void writeJson(HttpServletResponse response, int code, String msg) {
        response.setStatus(HttpServletResponse.SC_OK);   // 返回 200 + code=4001，前端按业务码处理
        response.setContentType("application/json;charset=UTF-8");
        try {
            response.getWriter().write("{\"code\":" + code + ",\"msg\":\"" + msg + "\",\"data\":null}");
        } catch (IOException ignored) {}
    }
}
```

注册时注意放行登录：

```java
@Configuration
public class MvcConfig implements WebMvcConfigurer {
    @Autowired private TokenInterceptor tokenInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(tokenInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/system/login", "/api/system/ping");
    }
}
```

> 如果你想省事，也可以不写拦截器，先写一个 `SystemController` 里的 `/api/system/ping` 返回 `R.ok("pong")`，把链路打通再做权限。

## 四、四步联调法（推荐节奏）

不要一上来把 37 个接口全写完再联调。**一次打通一条链**，每步都可验证。

### Step 0 · Apifox 先跑通（10 分钟）

把桌面的 `企业差旅管理工具 接口文档(对齐后端).openapi.json` 导进 Apifox（37 个接口，已与后端实现对齐）。后端写一个接口，就在 Apifox 里点一次。

**这一步的意义是把问题锁死在一侧**：Apifox 都不通，就是后端的问题，别去动前端。

### Step 1 · 只打通登录（第 1 天）

后端只实现三个接口：

| 接口 | 作用 | 验收标准 |
|---|---|---|
| `POST /api/system/login` | 返回 token + user（含 role） | Apifox 能拿到 token |
| `GET /api/system/me` | 拿 header 里的 token 返回用户信息 | 带 Bearer 能返回，不带返回 4001 |
| `POST /api/system/logout` | 让 token 失效 | 调用后前端能正常退出 |

然后把 `.env.development` 的 `VITE_USE_MOCK` 改成 `false`，重启 dev，`npm run dev` 开 `http://127.0.0.1:5173/`。

**验收四个点**（这一步过了，后面就顺了）：

1. 输 `wengshaogang / 123456` 能进 `/employee` 而不是跳到别的端口
2. 输 `manager / 123456` 能进 `/manager`
3. 手动改地址栏到别的角色路径（比如员工账号访问 `#/manager/report`）被踢回，提示无权访问
4. 刷新页面不退出（localStorage 里 TE_TOKEN 和 TE_USER 都在）

> 登录返回体的 `role` 字段值必须是 `EMPLOYEE / APPROVER / FINANCE / MANAGER` 之一，跟 `src/config/menus.js` 里的 `ROLE_META` 键名一致。写成 `employee` 小写或者 `1` 都会导致登录后卡在 `/login`。

### Step 2 · 按申请号主线推进（第 2–12 天）

顺序不能乱，**后面的功能依赖前面的数据**：

   ↓
D-01 预借额度 → D-02 提交报销（四维比对 + 预检）→ D-03 列表 → D-04 详情
   ↓
E-01 待复核 → E-02 四维比对 → E-03 复核结论 → E-04 付款
   ↓
F-01 月报 → F-02 钻取 → F-03 对象投入产出

## 五、排查清单：现象 → 原因 → 处理

| 现象 | 最可能的原因 | 怎么处理 |
|---|---|---|
| 页面一直转圈 / 数据不刷新 | `.env` 里 mock 还是 true，或改了没重启 dev | 改完必须 `Ctrl+C` 重开 `npm run dev` |
| F12 Network 没有请求发出 | 走的是 Mock adapter | 同上 |
| Network 报 404 | 后端 `context-path` 配了 `/travel`，但前端 baseURL 是 `/api` | 去掉 context-path，或改 `VITE_API_BASE` |
| Network 报 502 | nginx 起来了，后端没起 | 先看 Spring Boot 控制台，或直接访问 `http://127.0.0.1:8080/api/system/ping` |
| Network 报 CORS error | 形态 B 下不该出现；说明请求走了 8080 而不是 5173 | 检查是不是直接在浏览器访问了 8080 的页面 |
| Console 报 `Cannot read properties of undefined` | 返回结构对不上：分页字段名、或 VO 少字段 | 拿 Apifox 的响应和桌面那份「接口文档(对齐后端).openapi.json」的 schema 逐字段比对 |
| 字段值全是 null，但 SQL 能查到 | 下划线没转驼峰 | 检查 `map-underscore-to-camel-case: true` |
| 登录后立刻跳回登录页 | ① 拦截器把 login 也拦了 ② role 值不匹配 ③ `/system/me` 返回 4001 | 依次排查：放行 login → 打印 role → 看 Network 里 me 的响应 |
| 401 无限循环 | 后端返回 HTTP 401 而不是 code=4001，且拦截器没放行 login | 登录失败也走业务码 |
| 上传票据报 413 | multipart 或 nginx 上限没改 | 两边都改 10MB |
| 上传成功但影像打不开 | 影像路径是多级路径（2026/09/xxx.jpg） | 后端已是 `GET /api/invoice/file?path=&exp=&sign=` query 传参；前端别自己拼，直接用 `InvoiceVO.imgUrl` |
| 票据挂接成功但财务看不到影像 | C-02 确认时没带 `imgPath` | 确认挂接要把 C-01 返回的 `tempPath` 原样回传 |
| 中文全是 `???` | JDBC url 少了 `characterEncoding=utf8`，或 response 没设 charset | 按第三节的 yml 抄 |
| 时间字段显示 1970 或差 8 小时 | LocalDateTime 序列化没配 | `jackson.time-zone: GMT+8` + `@JsonFormat(pattern="yyyy-MM-dd HH:mm:ss")` |
| ECharts 图表空白 | 数据数组为空，或父容器高度为 0 | 先在 Console 打印接口返回值，确认不是渲染问题 |
| 月报趋势图没有线 | 后端 `MonthlyReportVO` 没有 trend 字段 | 前端自己按月查近 6 个月 F-01 拼（`MonthlyReport.vue` 的 `loadTrend`） |
| 财务待复核列表空 | 报销单都不是 `PENDING` 状态 | 跑 `数据库\重置联调测试数据.sql` |
| 调差标弹 1001「…已有标准，换一个生效日期」 | 同一（等级+交通方式+生效日期）已插过 | 换生效日期；或删掉旧行再测（后端现在提前查重，不再兜底成 5000） |
| 票据上传后票面字段全空 | OCR 没配，后端按「识别失败」返回 | 手工录入即可，影像已存好 |
| 部门下拉框只有基础四个 | 后端没有部门列表接口 | 读 `src/config/depts.js`（与 `dept` 表一致）；改了库同步这个文件 |
| 月报/对象页的费效比数字很大（如 171.43） | 跑的还是旧后端（`ratio` = 产出/投入） | 口径已统一成**投入 ÷ 产出**，重启后端即可；正常值应远小于 1（如 0.0058） |
| 费效比显示成 0.01 看不出差别 | 投入/产出普遍很小，两位小数被抹平 | `utils/dict.js` 的 `ratio()` 对小于 0.1 的值保留 3 位 |

**三步定位法**（碰到任何问题先做这三步，能解决 90%）：

1. F12 → Network → 找到那个请求 → 看 Status
2. 看 Response body，`code` 是多少、`data` 有没有内容
3. 把这个请求原样拿到 Apifox 里再打一次 —— Apifox 里也错就是后端问题，Apifox 里对就是前端解析问题

## 七、两条纪律

**1. Mock 不要删。** `src/mock/` 目录在后端没跑起来的时候是唯一的退路，答辩演示、给队友看效果都靠它。等全部接口联调通过、准备交作业了再删也不迟。

**2. 改字段要三方同步。** 一旦某个字段名变了，Apifox 接口文档 → 后端 VO → 前端 `src/api/index.js` 和页面，三处都要改。只改一处是联调失败最常见的原因。**推荐用 Apifox 的 mock 功能做字段校验**，字段对不上它会在响应校验里报红。

**3. 口径以 Apifox 文档为准。** 2026-09-22 已经做过一次三方统一（Apifox 与前端原本一致，
是后端改偏了，已把后端改回对齐它俩）。之后如果又要改字段名，先改 Apifox 文档，
再改后端，最后改前端 —— 顺序反过来就会出现「文档说 A、后端收 B」这种查半天的问题。
改动清单记在 `企业差旅管理工具-Apifox接口测试对照-逐步版.docx` 的附录 D。
