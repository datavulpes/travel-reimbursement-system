## 1. 起后端

后端目录：`D:\develop\Tutor-Student Matching Platform\travel-server`

**方式一（推荐）：双击 bat**

双击 travel-server 目录下的 `启动后端.bat`。
会弹出一个黑窗口，等它打印出：

```
Started TravelServerApplication in xx.xxx seconds
```

**这个黑窗口别关**，关了后端就停。首次启动 20~40 秒，之后两个定时任务会再预热点东西，稍等即可。

> 如果黑窗口一闪而过说找不到 jar：jar 没打出来。在 travel-server 目录下执行
> `mvn -o -DskipTests package`，然后再双击 bat。

**已经起过了就不用再起。** 一个端口只能跑一个后端，重复双击会直接报：

```
APPLICATION FAILED TO START
Description: Web server failed to start. Port 8080 was already in use.
```

这不是出错，说明已经有一个在正常工作。先探活确认一下：

```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/system/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"wengshaogang\",\"password\":\"123456\"}"
```

返回 `"code":0` 就用现成的，直接去第 3 步。**只有确认它没活着**才需要启动。

真要重启（比如刚重打了 jar）：先双击 `停止后端.bat`，再双击 `启动后端.bat`。
顺序反了会撞上同一个端口占用。

**方式二：命令行**

```bash
cd "${WORKSPACE}/Tutor-Student Matching Platform/travel-server"
java -jar target/travel-server-0.0.1-SNAPSHOT.jar
```

**确认起来成功了** —— 新开一个命令行窗口，执行：

```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/system/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"wengshaogang\",\"password\":\"123456\"}"
```

看到 `"code":0` 和一串 `token`，成了。

**停后端**：双击同目录的 `停止后端.bat`（它只杀监听 8080 的 java，不会动别的 Java 程序），或直接在黑窗口按 `Ctrl+C`。

### 底部导航按角色给不同的功能区

「工作台」和「我的」每个角色都有，中间的功能区只给真正干这活的角色——不属于本角色的功能连入口都不出现：

| 角色 | 底部导航 | 中间的功能区 |
|---|---|---|
| 员工 | 工作台 · 申请单 · 报销 · 我的 | 申请单、报销（自己填自己报） |
| 部门主管 | 工作台 · 审批 · 我的 | 审批（待我审批 / 已办） |
| 财务 | 工作台 · 财务 · 我的 | 财务处理（待复核 / 待付款） |
| 管理层 | 工作台 · 复审 · 概览 · 我的 | 复审、经营概览（差标与预算从概览页进） |
| 系统管理员 | 工作台 · 档案 · 我的 | 基础档案（往来对象、用户账号） |

两个实现上的点：

- **没用原生 tabBar**。它在 `pages.json` 里是写死的，项数改不了，更没法按角色换。现在是自研组件 `components/TabBar.vue` 读 `utils/tabs.js`，切页走 `redirectTo`（tab 之间不压栈，物理返回键退小程序）。
- **首页「全部功能」那一栏与底部导航同源**，都是读同一份 `tabsOf(role())`，所以两边不会出现「导航里有、首页没有」的错位。手输路径闯进别人的页面会被挡回工作台：审批、财务、概览、差标、档案五个页面各有守卫，判断的还是这份配置。

### 登录后工作台上会看到什么

工作台第一屏回答一句「有什么事在等我」，按角色不同：

| 角色 | 待你处理 |
|---|---|
| 员工 | 草稿没提交 / 被驳回待改 / 通过还没报销 / 报销被打回；没有待办时显示「在审批中 N 单」（可点进去看进度） |
| 主管 | 待我审批 N 条 |
| 管理层 | 待我复审 N 条 + 本月经营概览（费效比、投入、产出） |
| 财务 | 待复核 N 条、待付款 N 条 |

**演示库当前的实际数字**（用真后端跑出来的）：员工 2 单在审批中；主管待审批 3 条；管理层待复审 1 条；财务待复核与待付款都是 0（12 张报销单全付完了，要看复核流程得先用员工账号新提一张）。管理层概览在 10 月没数据时会自动退回 9 月（费效比 0.3849）。

点待办里的条目会直接跳到对应页面，员工的「草稿」「被驳回」会带着筛选条件跳到申请单列表（列表顶部以蓝色小标签显示当前筛选，点标签上的 × 即可放宽）。

### 列表页的筛选抽屉

申请单和报销列表左上角有「筛选」按钮，点开左侧滑出抽屉。抽屉里只有「状态」和「关键字」是真发给后端的（`ApplyQuery` 只认这两项），其余条件在已取回的单据里筛——一次拉 100 条，演示库全量都在里面。

- **申请单**：关键字（单号 / 事由 / 对象）、状态、往来对象（从列表里去重出来的）、差标结论（符合 / 接近上限 / 超出）、预估金额档位、提交日期区间（两个日期选择器）、排序
- **报销单**：关键字（报销单号 / 申请单号）、状态、预检结论（通过 / 有提醒 / 需填强制说明）、实付金额档位、提交日期区间、排序

生效的条件会以小标签挂在筛选按钮旁边（带红色角标数字），点标签上的 × 单独去掉一个。卡片上补了提交时间和差标 / 预检结论，筛完能直接对上。

### 列表分页

列表底部有分页条，**默认一页 10 条**，点左边的「10 条/页」可以换成 20 / 50 / 100（原生选择器）。右边是上一页 / 下一页，中间显示「共 N 条 · 第 x/y 页」。

- 这里的 N 是**筛完之后**的条数，不是库里总数；翻页和筛选是叠加的，改条件会自动回到第 1 页。
- 取数方式：后端一次最多给 100 条，页面进来时按 100 一页把能拿的都拿回来（上限 10 页），筛完再在本地切页。所以翻页不重新请求，改「状态 / 关键字」才会重新请求，改其余条件只重算。
- 演示库员工 14 单申请单、12 张报销单，默认 10 条一页刚好是两页，翻页效果直接看得到。

### 每个角色的列表都能筛、都能翻页

不只是员工的两个列表，审批、财务、档案、概览这几个角色的页面同样是「筛选抽屉 + 分页条」这一套，实现共用 `utils/paged.js` 的 `usePagedList`：

| 页面 | 交给后端的条件 | 本地筛的条件 |
|---|---|---|
| 申请单 / 报销（员工） | 状态、关键字 | 对象、差标 / 预检结论、金额档位、提交日期、排序 |
| 审批（主管、管理层） | 关键字、状态（待办 / 已办各一组） | 申请人、部门、评价等级、金额档位、提交日期、排序 |
| 财务（财务） | 关键字 | 报销人、预检结论、有无异常票、实付金额、提交日期、排序 |
| 基础档案 · 往来对象 | 对象名称 | 类型、是否被单据引用、累计投入、排序 |
| 基础档案 · 用户账号 | 姓名 / 登录名、角色 | 部门 |
| 经营概览（管理层） | 月份 | 「按部门」块：部门名、费效比区间（绿 / 黄 / 红 / 产出为 0）、排序；「往来对象」块：对象名、类型、排序 |

- **为什么不在后端分页**：后端每页最多 100 条，而筛选条件大多它不认。让后端分页、本地再筛，会出现「第 2 页筛完只剩 3 条」——条数和页码对不上。所以统一一次取回来本地筛 + 本地切页，翻页不请求。
- **概览页那两块是纯本地**：后端一次就把整月的投入产出算完了，筛费效比区间、翻页都不重新请求。
- 档案页的对象与用户是两套独立的筛选和分页，切分段时互不干扰。

### 经营概览的左侧分区导航

概览页是一屏装不下八个区块的，所以做成**左边一列索引、右边只渲染选中的那一块**（组件 `components/SideNav.vue`）。进页面默认落在第一块「总览」。月份选择器在顶部，八个区块看的是同一个月。

| 区块 | 内容 | 什么时候才发请求 |
|---|---|---|
| 总览 | 六个关键数字、本期结论、数据可信度（回填率 / 已付款单数） | 进页面就拉 |
| 部门 | 投入产出柱状图 + 部门明细（可筛、可翻页、点一行钻取） | 随月报一起回来 |
| 出差类型 | 各类出差的投入产出 + 投入占比条（可筛、可翻页） | 同上 |
| 产出构成 | 签单 / 验收 / 交付 / 无进展的条数与金额，无进展率 | 同上 |
| 趋势 | 近 6 个月费效比折线 + 0.40 警戒线 | **切到这一块才拉**（要按月查 6 次） |
| 往来对象 | 对象投入产出（可筛、可翻页） | 随月报一起回来 |
| 月度洞察 | 快照结论 + 「重新分析」 | 进页面读快照，只有点按钮才调模型 |
| 差标预算 | 差标摘要 + 各部门预算使用率，三个入口进维护页 | **切到这一块才拉** |

图表没有引第三方库：小程序里没有 echarts，也不值得为两张图引入 canvas 依赖。柱图是按最大值算百分比撑 `view` 的高度；折线是把两点之间用一根旋转的细条连起来（所以画布宽度写死成 rpx 常量——`sqrt(dx²+dy²)` 要的是真实长度，写百分比这条线会歪）。配色跟 Web 端一致：投入红、产出绿。

### 差标与部门预算在小程序里也能改了

从概览页「差标预算」那块进 `/pages/standard/standard`，左侧三块，和 Web 端的「标准配置」页对齐：

| 区块 | 能做什么 |
|---|---|
| 差标维护 | 新增一档（城市等级 + 交通方式 + 上限 + 生效日期）、调整（插新的生效日期行，旧版本留着追溯）、删除（只能删该组最新一档） |
| 部门预算 | 新增部门（含初始预算、差标等级）、调整月度预算、删除部门（名下有人或有单据时按钮置灰，后端也会拒） |
| 调整留痕 | 按类型 / 关键字查，分页。只追加，谁也不能改 |

- **每次改动都要填原因**，写进 `config_log`；不填不给提交。删除也走同一个弹层收原因，不用 `showModal` 的输入框（那玩意儿在部分基础库上不弹输入框，点了没反应）。
- 改完会把差标列表、部门列表、留痕一起刷新，不然留痕比数据慢一拍。
- 部门「已使用」是本月实际付款额，不是表里的一列——`dept` 表没有「已用」这个字段，跟 Web 端同一个口径。
- 这一整块接口在 `/config` 下，**后端限管理层**，别的角色进页面会被送回工作台。

**基础档案页**（只有 `sysadmin` 的导航里有）能做三件事：按名称搜往来对象、新增 / 改对象的名称与类型、删掉没被引用的对象（已被引用的按钮置灰并说明原因）。累计投入与产出只显示不给改——那两个数是付款和成果回填维护的，手一改就等于改报表。用户账号那一栏只做只读浏览，改姓名、部门、角色去 Web 端。

系统管理员在小程序里没有全表浏览——那是 17 张表的排查工具，留在 Web 端。

财务那两个列表当前是空的——演示库里 12 张报销单都已付完。

## 7. 两条容易卡住的业务约定

**（1）票据只挂在「已通过 / 已结案」的单子上**，不是存完草稿就能传。
后端在 `InvoiceService.upload()` 里按单据状态拦：状态不是 `APPROVED` 也不是 `CLOSED`

另外上传是两步：

再 `POST /invoice/confirm` 带上票面字段与挂哪一段，才真正落库。
中间的确认页让人能改 OCR 认错的日期和金额——OCR 把日期认错是常事。

**（2）出差类型这六个字不能改。**

**（2）出差类型这六个字不能改。**
`验货 / 商务拜访 / 项目交付 / 供应商审核 / 展会 / 其他`

## 8. 在手机上演示（真机）

模拟器用 `localhost` 没问题，**手机不行** —— 手机上的 localhost 是手机自己，手机要连电脑的**局域网 IP**。

### 8.1 先分清两条路

| 路 | 需要什么 | 二维码 | 能不能「不校验合法域名」 |
|---|---|---|---|
| **开发版（推荐，面试用这个）** | 开发者工具登录微信，用**测试号**也能扫 | 工具点「预览」生成，**25 分钟过期**，可随时再生成 | **能**，扫码后在手机上开调试即可 |
| **体验版** | 注册小程序拿正式 appid（个人主体可注册，免费、不用营业执照），上传代码后设为体验版 | 长期有效，体验成员扫码 | **不能**，必须配 https 已备案域名 |

结论：**面试现场用开发版扫码**就够了，不用备案、不用域名。体验版是「发给别人自己装」时才值得折腾。

### 8.2 五步走

**① 后端要开着，而且要对局域网可见**

后端默认监听 `0.0.0.0:8080`（`netstat` 能看到 `0.0.0.0:8080 LISTENING`），所以 IP 不是问题，**卡点通常是 Windows 防火墙**。放行一条入站规则（管理员身份跑一次，之后永久生效）：

```bash
netsh advfirewall firewall add rule name="travel-server 8080" dir=in action=allow protocol=TCP localport=8080
```

不想动防火墙就临时关掉「公用网络」的防火墙试一次，通了再改回来。

**② 确认手机和电脑在同一个网络**

```bash
ipconfig
```

找正在用的那张网卡的 IPv4。本机连校园网 WLAN 是 `10.77.54.139`（另两个 `192.168.x.x` 是 VMware 虚拟网卡，不是）。换网络 IP 会变，**每次换 WiFi 都要重查**。

**③ 手机上先探一下网络通不通**

用手机浏览器打开：

```
http://10.77.54.139:8080/api/config/depts
```

- 返回一串 JSON（哪怕内容是「未授权」），说明**网络通**；
- 一直转圈或「无法访问」，就是 IP 写错或防火墙没放行，先修这个，别急着扫二维码。

**④ 填后端地址**

默认地址已经是 `http://10.77.54.139:8080/api`（`src/utils/request.js` 里的 `DEFAULT_BASE`）。如果不是这个网络，**不用改代码**——小程序里「我的 → 后端地址」可以直接改，输 `http://<电脑IP>:8080/api`，末尾的 `/api` 不能少。
登录页底部也显示当前连的地址，扫一眼就知道连的是不是这台电脑。

**⑤ 生成二维码并开手机调试**

开发者工具顶部点 **「预览」** → 手机微信扫码。第一次在手机上要开一次调试：

小程序右上角 **··· → 开发调试 → 打开 → 自动重启小程序**（或用工具顶部的「真机调试」，它会帮你开好并弹出调试面板）。**只有开调试才允许访问非 https 的局域网地址**，否则手机会报 `url not in domain list`。

### 8.3 演示时的顺序

登录页有五个角色快填卡（点一下自动填账号密码），按业务流走一遍最有说服力：

```
员工 wengshaogang  新建申请单 → 保存草稿 → 传票 → 提交
      ↓
主管 daiqinghao    待我审批（看参考值与差标比对）→ 通过
      ↓
管理层 manager     复审通过
      ↓
财务 wusiting      复核 → 付款
      ↓
管理层 manager     概览：部门投入产出、趋势、月度洞察
```

### 8.4 现场容易翻车的几点

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 扫码后白屏 / 列表空，报 `url not in domain list` | 手机没开「开发调试」 | 右上角 ··· → 开发调试 → 重启小程序 |
| 请求一直超时 | 防火墙拦 8080，或 IP 变了 | 跑 ① 的放行命令；重查 `ipconfig` |
| 二维码扫不了 | 超过 25 分钟 | 工具里再点一次「预览」重新生成 |
| 手机上是旧界面 | 微信缓存了旧包 | 微信里删掉这个小程序（长按图标拖走），重新扫码 |
| 前一天还好好的，今天全挂 | 电脑休眠 / 后端黑窗口被关 | 后端窗口要一直开着，电源设置里把休眠关了 |
| 点「预览」**一点反应都没有** | 项目是**游客模式**（`project.config.json` 里 `appid` 是 `touristappid`） | 见 8.5 |
| 提示需要 AppID | 同上 | 见 8.5 |

**一步不需要 ICP 备案**，这只是局域网调试。备案和 https 域名是正式上线才要的。

### 8.5 点「预览」没反应 —— 九成是游客模式

原因已经确认过：编译产物 `project.config.json` 里写的是

```json
"appid": "touristappid"
```

`touristappid` 就是**没登录、没 AppID 的游客模式**。游客模式只能跑模拟器，**「预览」和「真机调试」直接不可用**（点了没反应或弹「请先登录」）。

**解法 A：用测试号（最快，两分钟）**

1. 开发者工具右上角头像 → **用微信扫码登录**（不登录一切免谈）；
2. 「详情 → 基本信息 → AppID」这一行点 **「修改」** → 弹窗里选 **「测试号」**（有的版本叫「申请测试号」），工具会分配一个 `wx` 开头的真实 AppID；
3. 如果面板里找不到「测试号」入口，走网页直取：浏览器打开 **<https://mp.weixin.qq.com/wxamp/sandbox>** → 微信扫码登录 → 页面上直接给你 **appID**，复制下来；
4. **关键一步**：测试号只写进了 `project.config.json`，而 uni 每次重新编译都会用 `manifest.json` 里的值把它覆盖回 `touristappid`。所以把那个 `wx` 开头的 AppID 填进 `小程序端\src\manifest.json`：

   ```json
   "mp-weixin" : {
       "appid" : "wx 开头那串",
       ...
   ```

4. 重新编译一次（`npm run dev:mp-weixin`），再点「预览」。

测试号能预览、能真机调试，**不能上传代码、不能发体验版** —— 演示扫码用足够了。

**解法 B：注册个人小程序（要发体验版时）**

浏览器打开 <https://mp.weixin.qq.com> → 立即注册 → **小程序 → 个人主体**（免费、不用营业执照，填身份证即可，当场拿到 AppID）→ 把 AppID 填进 `manifest.json` 的 `mp-weixin.appid` → 重新编译。
之后还能「上传代码 → 设为体验版」，体验成员扫码就能装，二维码长期有效。

**另外两种「以为没反应」的可能**

- **编译还没跑完**：看工具底部状态栏 / 编译日志，出现「编译完成」再点预览；
- **二维码窗口被挡住了**：预览的二维码是独立小窗，可能被主窗口盖住，看一眼任务栏。

### 8.6 设为体验版（先看完这段再决定要不要做）

体验版的好处很明显：二维码**长期有效**、面试官自己微信里就能装、不用坐在你电脑旁边。但有一堵硬墙必须先看清。

**墙在这儿：体验版不能跳过域名校验。**

开发版能用「不校验合法域名」访问 `http://10.77.54.139:8080/api`，体验版和正式版**不行**——服务器域名必须是 **https + 已 ICP 备案 + 配到后台的 request 合法域名**（IP 和端口都不认）。也就是说，要发体验版，后端必须挂在一个已备案的域名下。

所以现实的路只有三条：

| 路 | 要多久 | 适合 |
|---|---|---|
| **开发版扫码（8.1~8.5）** | 现在就能用 | 当面演示，电脑联网就行 |
| **体验版 + 已备案域名 + 云服务器** | 有现成域名：几小时；现买：备案要 1~3 周 | 对方自己装、异地演示 |
| 体验版 + 内网穿透 | **走不通** | cpolar 之类的免费域名无法备案，微信后台会拒 |

**如果你已经有（或愿意买）域名和服务器，操作就这几步：**

1. **拿正式 AppID**：<https://mp.weixin.qq.com> 注册 → 小程序 → 个人主体（免费、填身份证，当场出 AppID）。测试号不能用在这条路上。
2. **填进 manifest 并重新编译**：`src/manifest.json` 的 `mp-weixin.appid`，跑一次 `npm run build:mp-weixin`（生产产物，别传 dev）。
3. **后端配 https**：云服务器上 nginx 反向代理到本机/云上的 8080，申请 SSL 证书（各家有免费的单域名证书），小程序只认 443 端口，**不能带端口**。
4. **微信后台配域名**：mp.weixin.qq.com → 开发 → 开发管理 → 开发设置 → **服务器域名 → request 合法域名**，填 `https://你的域名`。这里会校验域名备案信息，没备案会直接拦下。
5. **上传代码**：开发者工具右上角 **「上传」** → 填版本号（如 1.0.0）和项目备注 → 上传成功。
6. **设为体验版**：后台 → 管理 → **版本管理** → 开发版本那一行点 **「设为体验版」**。
7. **加体验成员**：后台 → 成员管理 → 体验成员 → 添加面试官的微信号。加完之后生成**体验二维码**，长期有效，对方扫码即可，不再依赖你的电脑。

**上传前两件事**：用生产产物 `dist\build\mp-weixin` 去上传，别拿 dev 产物；代码质量那两项（JS 压缩、按需注入）已经在 8.2 处理过，上传前可以把检查跑一遍确认全绿。
